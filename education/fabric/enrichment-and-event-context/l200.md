## Define acceptance before implementing

For batch enrichment, agree on allowed categories, missing-input behavior, quality thresholds,
model/prompt version and review rules. Create independent labels before evaluating candidate
outputs. Reject malformed output rather than storing a plausible default.

For events, define an event key, occurrence time, acceptable context age and late-event policy.
Use a scratch synthetic sequence containing normal, duplicate and delayed events. Decide whether
late context should revise a proposal or be rejected; do not let an assistant invent the rule.

## Recovery and authority

Keep failed inputs observable and retry only within a bounded policy. Reconcile derived results
to their source records. A replay must not create another authoritative action for the same event.
Any live notebook run or resource change requires a separate governed plan and approval.
