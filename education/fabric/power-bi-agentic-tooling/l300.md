## Through MCP (ffia-local)

| Tool | What it does | Live equivalent |
|---|---|---|
| `evaluate_measures(profile, measures)` | Evaluates declared measures by name - no free-form SQL or DAX | DAX query through Fabric IQ MCP |
| `evaluate_against_baseline(profile, observed, observed_label)` | Compares observed values with the baseline within the overlay tolerance | The same, with values pasted from live DAX checks |
| `get_guide_step("hc-01-fabric-mcp-powerbi-medallion-lab", "12-relationships-and-measures")` | Returns the step's prompts, checkpoint and required evidence | - |

`evaluate_measures` returns `execution_label: LOCAL` and
`equivalent_fabric_service: Power BI semantic model DAX query (Direct Lake)`. If you paste
values from a live DAX run into `evaluate_against_baseline`, label them honestly; values the
accelerator did not retrieve itself are recorded as **REQUIRES TENANT VALIDATION**. A pass rate
below 1.0 fails the gate.

## The live flow (HC-01, steps 11-15)

1. **Connect, read-only** - Power BI Authoring MCP (local) connection and inspection tools.
2. **Propose, then apply** relationships and measures - approval required; then run DAX checks
   and reconcile.
3. **Review** for best practices and AI readiness - read-only.
4. **Report** - plan two pages, build PBIR bound to the model, validate, stop before publishing.
5. **Validate** - a table of checks with provider, tool, result and evidence.

The opt-in `powerbi-modeling-sandbox` profile in `config/mcp/profiles.yaml` pins
`@microsoft/powerbi-modeling-mcp@1.0.0` against a LOCAL PBIP sandbox copy with per-call approval;
a person accepts the EULA, the rendered config never does. The authoring skills come from
`microsoft/skills-for-fabric` v0.3.18 (not installed by the accelerator).
