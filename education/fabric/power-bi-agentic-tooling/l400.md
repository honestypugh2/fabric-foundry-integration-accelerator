## Where agentic model authoring goes wrong

| Failure | Symptom | Control |
|---|---|---|
| Wrong grain | Encounter counts multiplied by joining child rows | Facts at one declared grain; children pre-aggregated in Gold |
| Ambiguous filter paths | Two active date relationships, or fact-to-fact paths | One active date role per fact; exclude aggregate tables from the model |
| Averaging averages | ALOS computed from a grouped aggregate table | Compute ratios from additive components (`DIVIDE(SUM, COUNT)`) |
| Blank handling drift | DAX and SQL treat blanks differently | Define blank handling in the measure contract; reconcile both |
| Invented measures | Agent adds a metric with no valid denominator | Contract lists excluded measures with reasons (bed occupancy) |
| Wrong model | Agent connects to a similarly named model | Connect by exact model ID; confirm identity before any write |
| Fake completion | "Report published" based on a valid local PBIR | Require the published report ID, workspace ID and model binding |

## Enforcement details

- **Proposal then apply.** The guide separates authoring prompts from execution prompts and
  requires approval for `update_semantic_model` and `publish_report` in the example overlay.
- **Reconciliation is deterministic.** The baseline is produced by `ffia data build` from Gold
  Parquet; comparison uses an absolute tolerance from the overlay (`1e-6`) and a minimum pass
  rate of 1.0. Missing measures are reported, not ignored.
- **Read and write tools stay separate.** Fabric IQ MCP is read-only and enforces RLS/OLS for
  the caller; Authoring MCP needs XMLA read/write on the capacity and model edit rights.

## Threat model

- **Metadata exposure.** Model names, descriptions and measure logic flow into the agent's
  context and logs. The Authoring MCP project warns that models can leak sensitive metadata;
  use clients approved for that data and back up models before edits.
- **Prompt injection through descriptions.** Text in table or measure descriptions can instruct
  an agent. Review descriptions like code; keep writes behind approval.
- **Hosted preview drift.** The hosted authoring endpoint is preview; keep it behind the
  `powerbi_hosted_authoring_mcp` flag and validate before use.

## Direct Lake considerations

Direct Lake reads Delta tables in place, so Gold table design (types, partitioning, file layout)
directly affects model behavior and fallback. Validate guardrails and fallback behavior for your
capacity in the tenant - this is **REQUIRES TENANT VALIDATION**.
