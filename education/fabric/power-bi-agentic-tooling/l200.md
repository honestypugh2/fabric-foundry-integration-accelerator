## Components and boundaries

| Component | Reads | Writes | Identity | Status |
|---|---|---|---|---|
| PBIP / TMDL / PBIR in Git | Files | Files (via PR) | Git permissions | GA |
| Power BI Authoring MCP - local | Desktop and PBIP files, models via XMLA | Tables, relationships, measures, roles | Entra sign-in in the client | GA 1.0.0 |
| Power BI Authoring MCP - hosted | Fabric semantic models | Model changes | Entra | PREVIEW |
| Fabric IQ MCP | Models, metadata, DAX results | Nothing | Entra delegated, RLS/OLS enforced | GA |
| Authoring skills | - | Instruct the agent | Inherit the session | Open source, pre-1.0 |
| Fabric Git integration | Item definitions | Sync workspace and repository | Workspace + repo permissions | GA |

Use **Fabric IQ MCP** to *query* models and **Power BI Authoring MCP** to *author* them. Do not
use an authoring server for read-only checks.

## The model design in this accelerator

The contract in `data/synthetic/semantic/hc-lab-7file-v1/semantic-model.yaml` describes a Direct
Lake star schema over Gold:

- Three facts at clear grains: `gold_encounter_summary` (encounter), `gold_financial` (claim),
  `gold_readmissions` (index inpatient encounter).
- Shared dimensions `dim_date`, `dim_patient`, `dim_facility`, `dim_payer`.
- One-to-many, single-direction relationships; one active date role per fact.
- Aggregate tables (`gold_alos`, `gold_ed_utilization`, `gold_population_health`) excluded so
  averages are never averaged and facts never filter each other.
- Each measure has a definition, format, reference DAX and an equivalent SQL; a bed occupancy
  measure is excluded because no denominator exists.

## Data and evidence flows

1. Gold Delta tables → Direct Lake model (no import copy).
2. Proposed TMDL change → review → apply through Authoring MCP (writes, approval required).
3. DAX checks → compared with the expected baseline → pass or fail per measure.
4. PBIR report bound to the validated model → preview → publish (approval required).

## Trade-offs

- **Local vs hosted authoring.** Local reaches PBIP files and Desktop and is GA; hosted needs no
  Desktop but is preview and edits the service model directly.
- **File-first vs live edits.** Editing TMDL in Git gives a reviewable diff; live edits are
  faster but need a separate record of what changed.
- **Direct Lake vs Import.** Direct Lake avoids copies and refresh lag but depends on Gold table
  design and capacity guardrails.

## Online vs offline

Offline, the Local Fabric Educational Provider evaluates the same measure contracts with DuckDB
over Gold Parquet and labels results `LOCAL`. The PBIP project and live DAX checks need a tenant
and arrive with Phase 5.
