## How a skill actually executes

1. The harness reads skill descriptions and decides a request matches one.
2. The agent loads `SKILL.md` into context and follows its procedure.
3. The procedure tells the agent to run commands - typically `az rest` against the Fabric REST
   API with an `x-ms-fabric-skill` header, or SQL, KQL and PySpark through other tools.
4. The harness's permission system decides whether each command or MCP call needs approval.
5. Fabric authorizes the call against the token's identity.

Steps 1-3 are probabilistic and content-driven. Steps 4-5 are the only deterministic controls.

## Failure modes

| Failure | Cause | Control |
|---|---|---|
| Overreach | Skill runs a write the user did not intend | Harness approval for writes; read-only identity for exploration |
| Wrong target | Agent picks a workspace by name, or the CLI is signed in to another tenant | Pin tenant; verify with a read; use exact item IDs for writes |
| Stale or changed knowledge | Pre-1.0 skill changes between versions | Pin release; review the changelog and diffs like code |
| Silent substitution | An MCP tool fails and the agent improvises with REST | Rule: report the limitation and stop |
| Bundled wildcards | `tools: ["*"]` on an authoring server | Hardened overlay with explicit allow-lists |
| Arbitrary SQL | `execute_query` on the SQL endpoint server | Off by default; item-scoped; read-only SQL role |

## Threat model

- **Supply chain.** A skill is instructions an agent will follow. A malicious or careless change
  in a skill is equivalent to a change in a runbook executed with your credentials. Treat the
  skills repository as a dependency: pin, review, and update deliberately.
- **Prompt injection.** Content read during a task (file contents, item descriptions, query
  results) can try to override skill instructions. Keep write tools behind approval.
- **Credential reach.** `az login` tokens on a workstation are usable by any process the agent
  starts. Use dedicated lab machines or containers and   short-lived sign-ins.

## Evidence that is not evidence

A skill reporting "done", a file existing in a workspace, or a matching byte size is not proof of
a correct operation. Require Fabric operation results, a read-back check, and - for changes - a
pull request and audit record.
