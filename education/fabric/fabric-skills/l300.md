## Installing (on a lab machine, against a dev workspace)

GitHub Copilot CLI:

```text
/plugin marketplace add microsoft/skills-for-fabric
/plugin install fabric-skills@fabric-collection
/plugin install powerbi-authoring@fabric-collection
```

Claude Code uses the same marketplace mechanism:

```bash
claude plugin marketplace add microsoft/skills-for-fabric
```

A single skill can be installed with APM:

```bash
apm install microsoft/skills-for-fabric --skill spark-cli --target copilot
```

Sign in first, pinned to the intended tenant: `az login --tenant <TENANT_ID>`. Keep the tenant
and workspace identifiers in git-ignored local files only.

## Inspect before you trust

After installing, open the plugin folder and read:

- each `SKILL.md` you plan to use - what commands it will run and with which permissions;
- the bundled `.mcp.json` - which servers and which tools are allowed;
- the persona agent files - which skills they route to.

Then **replace** the bundled MCP servers with your own allow-listed profile. In Copilot CLI and
Claude Code, keep tool approval prompts on for shell and MCP write tools.

## What this repo provides today

- `.mcp.json` registers only `microsoft-learn` and the LOCAL `ffia-local` server. No Fabric
  Skills servers are installed by the accelerator.
- `config/mcp/profiles.yaml` defines the pinned profiles: `offline` (the default; `.mcp.json` is
  this profile rendered), `fabric-docs`, `fabric-readonly`, `fabric-authoring-gated` (opt-in,
  per-call approval) and `powerbi-modeling-sandbox`. There is no separate skills profile:
  replace a skill bundle's MCP configuration with `ffia mcp render fabric-readonly`.
- `ffia-local` offers the governed half of a skill workflow offline: an agent can call
  `inspect_medallion_architecture`, `preview_table` and `generate_fabric_change_plan`, but it
  cannot approve or execute.
- The accelerator's own repository skills under `.claude/skills/` (the folder both Copilot and
  Claude Code read) are planned alongside the Phase 7 prompt packs.

## A safe first exercise

Ask the agent, with the `e2e-medallion-architecture` skill loaded, to **plan** a medallion
design for the `hc-lab-7file-v1` profile without calling any Fabric API. Compare its plan with
the offline build:

```bash
ffia data build --profile hc-lab-7file-v1
```

Then ask `ffia-local` for `inspect_medallion_architecture` and check whether the plan's tables
and grains match the 7 Bronze, 7 Silver and 10 Gold tables that were built. Results are labeled
`LOCAL`; nothing ran in Fabric.
