## Components and boundaries

| Layer | Fabric Skills provide | Fabric Skills do not provide |
|---|---|---|
| Knowledge | SKILL.md procedures, routing rules, gotchas, reference files | Guarantees that the knowledge is current for your tenant |
| Execution | Instructions to call Fabric REST through `az rest`, plus SQL, KQL and PySpark | A sandbox; commands run on your workstation |
| MCP | A bundled `.mcp.json` that registers servers | Safe defaults for production |
| Authority | Nothing | Any permission - the identity you signed in with decides |
| Evidence | A telemetry header (`x-ms-fabric-skill`) on REST calls | An audit trail you control |

## Identity path

Skills expect an Azure CLI sign-in. Every REST call is made with a token for the signed-in
user, so the skill can do anything that user can do in Fabric - including in workspaces you did
not intend to touch. Pin the tenant (`az login --tenant`), use a dev workspace, and prefer an
identity with only the roles the task needs.

## The bundled MCP configuration (verified as of October 2026)

| Server | Endpoint type | Tools allowed | Risk |
|---|---|---|---|
| `FabricIQ` | Remote, read-only | `*` | Low; read-only and permission-enforced |
| `powerbi-modeling-mcp` | Hosted authoring (PREVIEW) | `*` | Write-capable semantic-model changes |
| `fabric-sqlendpoint` | Data Warehouse MCP (PREVIEW) | `execute_query` | Arbitrary T-SQL under your identity |

Installing the bundle as-is gives an agent write-capable authoring and arbitrary SQL under your
identity, in preview services.

## The hardened overlay

The accelerator has no separate skills profile file. The hardening is the profile approach in
`config/mcp/profiles.yaml`: keep the skills but replace the bundled server list with a rendered,
pinned profile (`ffia mcp render fabric-readonly`):

1. **Dev workspace only**, pinned tenant.
2. **Read-only by default:** `fabric-readonly` (16 allow-listed metadata read tools) or
   `fabric-docs` (6 docs tools), each with an explicit tool list and `--read-only`.
3. **Authoring is opt-in:** `fabric-authoring-gated` and `powerbi-modeling-sandbox` (local PBIP
   sandbox copy) are separate profiles with per-call approval.
4. **Arbitrary SQL is off** behind the `data_warehouse_mcp` preview flag.
5. **Approvals on** in the harness; production changes go through Git and pull requests.

## Trade-offs

- **Speed vs control.** Skills plus a permissive harness are fast for exploration; for anything
  that must be repeatable, use the repo-first path (P20) and let skills author files for review.
- **Persona agents vs explicit skills.** Persona routers are convenient but experimental;
  naming the skill makes behavior easier to review and reproduce.
- **Online vs offline.** Skills need a tenant to execute. Offline, the accelerator teaches the
  decision model and runs the equivalent steps against the Local Fabric Educational Provider.
