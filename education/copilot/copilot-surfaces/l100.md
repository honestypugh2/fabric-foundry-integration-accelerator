## What a surface is

A **surface** is where you talk to Copilot. Underneath, the surfaces share one agent runtime: the
same skills, MCP servers and repository instructions work across them.

```text
             repository rules (AGENTS.md, instructions) + skills + .mcp.json
                                       │
   ┌──────────────┬──────────────┬─────┴────────┬────────────────┬──────────────┐
   VS Code        Copilot CLI    Copilot app    Cloud agent      Copilot SDK
   (editor)       (terminal)     (desktop,      (GitHub Actions, (your app)
                                  preview)       issue → PR)
```

## Each surface in one line

- **VS Code agent mode** — Copilot edits files, runs terminal commands and calls MCP tools in your
  editor, asking before risky steps.
- **Copilot CLI** — the same agent in your terminal, with a plan mode and a headless `-p` option
  for scripts. Generally available since February 2026.
- **Copilot app** — a desktop app where each session runs in its own git worktree, in Interactive,
  Plan or Autopilot mode. Technical preview.
- **Copilot cloud agent** — assign a GitHub issue; the agent works in a sandbox and opens a pull
  request for you to review.
- **Copilot SDK** — embed the agent runtime in your own tool.

## Files that steer every surface

| File | Purpose |
|---|---|
| `AGENTS.md` | The rulebook for every agent |
| `.github/copilot-instructions.md` | Copilot's summary of the rules |
| `.github/instructions/*.instructions.md` | Rules for certain paths, such as `education/**` |
| `.mcp.json` | Which MCP servers to start |
| `.claude/skills/` | Skills both Copilot and Claude Code can load |

## Key ideas

- **Same rules, different place.** Choose the surface for the job, not for different rules.
- **Approval moves.** Locally you approve tool calls; with the cloud agent you approve the pull
  request.
- **Preview is labeled.** The Copilot app and sandboxes are previews and are never required by
  the default demo.
