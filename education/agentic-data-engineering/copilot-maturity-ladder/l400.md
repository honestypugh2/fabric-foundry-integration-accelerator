## Failure modes per level

| Level | Failure mode | Enforcement that holds |
|---|---|---|
| L1 | Code compiles but uses a non-existent Fabric API or wrong item format | Review, tests, CI |
| L2 | Documentation tool version drifts; instructions conflict | Pin server versions; one source of truth (`AGENTS.md`) imported elsewhere |
| L3 | Skill bundle ships an MCP config with write-capable servers and all tools allowed | Hardened overlay; skills pinned to a tag |
| L4 | Agent reads the wrong tenant or workspace; prompt injection inside data | Target pinning, read-only allow-list, bounded previews |
| L5 | Agent tries to approve or execute its own plan | No approve/execute tool over MCP; separation of duties; destination binding |
| L6 | Many sessions fan out, cost and blast radius grow | Sandbox, firewall, budgets, CI gates on every PR |

## Instructions are context, not enforcement

`AGENTS.md`, instruction files and skills shape what the model *tries*. They do not stop it. What
actually stops an action:

- **Tool absence.** `ffia-local` exposes no approve, execute, SQL or shell tool, so no prompt can
  make it write.
- **Harness permissions.** Per-tool approval in Copilot CLI and VS Code; deny rules; Claude Code
  hooks.
- **Platform authority.** Entra identity, Fabric workspace roles, branch protection.
- **Deterministic policy.** `config/policies/writes.yaml` evaluated in code, not by the model.

## Specific risks to name

- **Skills run with your identity.** A skill that calls `az rest` uses your token and roles. The
  `x-ms-fabric-skill` telemetry header sent with each call carries the skill name.
- **Arbitrary T-SQL.** The Data Warehouse MCP (preview) exposes `execute_query`; keep it off by
  default and use a read-only SQL role in labs.
- **Cloud agent.** No per-call approval once MCP is configured, and its firewall does not restrict
  MCP server processes — give it read-only or offline tools only.
- **Autopilot and bypass modes.** Only inside a sandbox with synthetic data.

## Measuring honestly

Scorecards are vulnerable to confounders: model choice, prompt wording, warm caches, a learner
who has already seen the task. Mitigations: fixed task wording, the same model where both
harnesses allow it, several runs, and recording failures as well as successes. Report
*observations on this repository*, never general product claims.

## Production gaps

- A hardened MCP overlay and live read-only profiles arrive in Phase 5.
- A live scoped writer with an Entra identity limited to one workspace does not exist yet; approved
  LIVE plans return `UNAVAILABLE` and are never redirected to LOCAL.
- Headless review in CI (P23) and the bake-off arrive in Phase 7; security CI in Phase 8.
