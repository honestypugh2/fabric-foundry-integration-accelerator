## Climbing the ladder in this repository

**L1 Assisted.** Open a Silver transform and ask Copilot to explain it:

```text
src/fabric_foundry_accelerator/synthetic/sql/silver/silver_encounters.sql
```

Evidence is the conversation and any diff you accept.

**L2 Grounded.** The repository already grounds every harness:

- `AGENTS.md` (rules), `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md`.
- `.mcp.json` registers `microsoft-learn` (documentation, needs network) and `ffia-local`.

Ask a question twice — once without instructions, once with — and compare the answers.

**L3 Skilled.** Installing Skills for Fabric is optional and online:

```text
/plugin marketplace add microsoft/skills-for-fabric
/plugin install fabric-skills@fabric-collection
```

Offline, point the agent at the repository docs instead. Skills live in `.claude/skills/`, the
one folder both Copilot and Claude Code read: the pinned Fabric Skills (`ffia skills install`) and
the accelerator's own `ffia-governed-fabric-change` skill.

**L4 Connected (local).** Start `ffia serve mcp` (or let the harness start it from `.mcp.json`) and
call read-only tools:

```text
inspect_medallion_architecture(profile="hc-lab-7file-v1")
preview_table(profile="hc-lab-7file-v1", table="silver_encounters", limit=5)
evaluate_measures(profile="hc-lab-7file-v1", measures=["total_encounters"])
```

Every envelope carries `execution_label: LOCAL`, `cloud_operation_performed: false` and a
`correlation_id`. The pinned `fabric-readonly` profile in `config/mcp/profiles.yaml` (16
allow-listed metadata read tools) is the next rung; rendering it and listing its tools is LOCAL,
while calling them against a tenant REQUIRES TENANT VALIDATION.

**L5 Governed change.** The agent may call `generate_fabric_change_plan` (for example a LOCAL
`create_notebook`). A **different person** approves through `POST /api/v1/approvals`, and
execution goes through `POST /api/v1/fabric/change`. `get_audit_record` returns the trail.

**L6 Parallel.** Documentation only here; the Copilot app is a technical preview.

## The scorecard

Record one row per task per level:

| Metric | How to capture it here |
|---|---|
| Time | Wall clock from prompt to accepted result |
| Steps | Prompts plus tool calls in the transcript |
| Approvals requested | Tool-permission prompts and plan approvals |
| Checks passed | `pytest`, `ruff`, `pyright`, `ffia data build`, baseline comparison |
| Evidence completeness | Correlation IDs, labels, plan, approval, audit record present |
| Errors caught | Wrong APIs, unsafe requests or bad SQL stopped before merge |

Use `evaluate_against_baseline` to check that a change did not move the expected Gold measures.

## Tests that back the claims

`tests/unit/test_mcp_server.py` covers the tool surface and labels;
`tests/unit/test_config_policy_changes.py` covers plans, approvals and refusals.
