## The ladder, level by level

| Level | You add | Copilot does | Value | Main risk |
|---|---|---|---|---|
| L0 | — | Nothing | Baseline | Human error |
| L1 | VS Code + Git-synced items (`notebook-content.py`, TMDL) | Completes and explains code | Speed | Plausible but wrong Fabric APIs |
| L2 | `AGENTS.md`, instruction files, Fabric MCP (local) docs tools | Uses real schemas, API specs, best practices | Correctness | Stale knowledge |
| L3 | Fabric Skills + repo skills | Follows Microsoft procedures and gotchas | Consistency | Skills act with your full permissions |
| L4 | Read-only remote MCP (Fabric IQ, OneLake, SQL) | Inspects real items | Real context | Data exposure, wrong tenant |
| L5 | Plan → approve → deploy via Git or a scoped writer | Proposes changes as plans and PRs | Safe velocity | Unapproved writes |
| L6 | Copilot app worktrees, cloud agent fleets, Agent HQ | Parallel migrations | Throughput | Runaway autonomy, cost |

| Level | Control | Evidence | Offline equivalent |
|---|---|---|---|
| L1 | Human review | Diff | Local SQL over synthetic data |
| L2 | Pinned server versions | Tool-call log | Docs tools need no tenant |
| L3 | Hardened MCP overlay, dev workspace | Skill name in audit | Skills read as Markdown; local provider |
| L4 | Read-only allow-list, target pinning | Correlation ID, request IDs | `ffia-local` read-only tools |
| L5 | Approvals, branch protection, CODEOWNERS | PR + audit + deployment log | Simulated execution, labeled |
| L6 | Sandbox, firewall, MCP allow-list, budget | Session logs, PRs | Scripted sessions, synthetic repo |

## Boundaries

- **Knowledge never executes.** A skill describes `az rest` calls; the harness runs them as you.
- **Execution never authorizes.** MCP servers run with the caller's Fabric permissions.
- **Authority sits outside the agent.** Approval happens in the API, UI or PR review.

## Identity paths

| Surface | Acts as | Approval point |
|---|---|---|
| CLI / VS Code | The developer | Per-tool prompts |
| Cloud agent | Repository-configured tools in an Actions sandbox | The pull request (no per-call approval) |
| Scoped writer (L5) | A separate least-privilege identity | Human approval before execution |

## Trade-offs

- Each rung must add its control **before** its capability; higher levels widen blast radius.
- L5 adds friction deliberately; reads and exploration do not need it.
- Every rung through L5 has an offline counterpart here, but the model still needs network access.
