## Why specify first

A rapid prototype should test a business hypothesis, not accumulate features without a success
criterion. Name the user, desired decision, measurable outcome, exclusions and owner before
asking an agent to implement the solution.

## When to use it

Use specification-driven work for new use cases or changes crossing data, APIs, UI and
governance. A typo or narrow repair with a clear reproduction usually needs a direct fix and
test, not a large planning ceremony.

## What Spec Kit adds

Spec Kit organizes requirements, design, tasks and completeness review. It is optional developer
tooling, not an application dependency, model runtime or deployment authority. The repository
also supplies a LOCAL procedure usable without installing the upstream CLI.

## Evidence

Require a trace from each promised outcome to a test and observed result. A checked requirements
quality item does not prove implementation completion. Human review and the existing governed
change flow remain necessary before cloud mutation.
