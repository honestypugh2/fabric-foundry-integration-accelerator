## From outcome to contract

Start with the user and measurable behavior. Separate functional requirements, quality
requirements, assumptions and exclusions. Map each acceptance criterion to a test or explicitly
manual observation before writing a task list.

## Integration choices

The shorter upstream path uses specify, plan, tasks, implement and converge after establishing
the constitution. The full path adds clarification, requirement checklists and consistency
analysis. Use the fuller path when identity, preview behavior and multiple layers interact.

## Guardrails

The repository's instructions remain authoritative. Optional initialization must be trialed in
scratch space; generated Skills can overlap with existing Copilot and Claude customization.
Never overwrite MCP configuration, instructions or policy just to make an initializer succeed.

## Active feature

Spec Kit resolves the active feature from `.specify/feature.json` or
`SPECIFY_FEATURE_DIRECTORY`. Checking out a Git branch alone does not switch that state.
Confirm the selected feature before implementing tasks.
