## What it is

A specification describes what users should be able to do and why. A plan describes how the
team intends to build it. Tasks divide that plan into work. Tests and observations check whether
the promise was met. These artifacts serve different purposes.

## The full workflow

Constitution, specify, clarify, plan, checklist, tasks, analyze, implement and converge.
Current Spec Kit agent Skills use names such as `/speckit-specify`; they are chat invocations,
not terminal commands.

## Worked example

Specify that a user can inspect a synthetic sales question, see its baseline and distinguish
LIVE from LOCAL fallback. Do not write merely "build a modern agent." Add concrete failure
behavior: unavailable live context must be disclosed; a fallback cannot pass live certification.
