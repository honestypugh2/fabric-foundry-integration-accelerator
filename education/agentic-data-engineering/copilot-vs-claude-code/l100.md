## What they are

- **GitHub Copilot** is a family of agent surfaces — VS Code agent mode, Copilot CLI, the Copilot
  app (preview), the Copilot cloud agent — that share one agent runtime and can use many models,
  including Claude models.
- **Claude Code** is Anthropic's agentic tool for the terminal, IDE and desktop, with its own
  permission modes, subagents, hooks and a GitHub Action.

Both are **harnesses**: they wrap a model in a loop of planning, tool calls and approvals. Neither
is the model, and neither is an authority over your Fabric workspace.

## What they share in this repository

```text
AGENTS.md ─────────────► GitHub Copilot (reads it directly)
    ▲
    └── CLAUDE.md (@AGENTS.md import) ──► Claude Code

.mcp.json      ──► both: microsoft-learn (docs) + ffia-local (synthetic)
.claude/skills ──► both: the one skill folder each harness reads
prompts/, labs ──► same tasks, same scorecard
```

Claude Code reads `AGENTS.md` only when there is no `CLAUDE.md`, so this repository's `CLAUDE.md`
imports it. One rulebook, two harnesses.

## Key differences in plain words

| Topic | GitHub Copilot | Claude Code |
|---|---|---|
| Asking before acting | Per-tool approval, allow and deny rules | Named permission modes |
| Planning first | Plan mode in CLI; Plan in the app | Plan permission mode |
| Hard blocks | Tool rules and org policy | Hooks |
| Working on GitHub issues | Cloud agent opens pull requests | GitHub Action; Claude via Agent HQ |
| Scripts and CI | `copilot -p` | `claude -p` |

## Key ideas

- **Same assets, different harness.** Write rules once; both read them.
- **Instructions guide; they do not enforce.** Enforcement comes from tools, permissions,
  identity and policy.
- **Measure, do not assume.** The bake-off compares harnesses on identical tasks.
