## Components compared

| Dimension | GitHub Copilot | Claude Code |
|---|---|---|
| Instructions | `copilot-instructions.md`, `.github/instructions/*`, `AGENTS.md` | `CLAUDE.md` (imports `AGENTS.md` here) |
| Skills | `.github/skills`, `.claude/skills`, `.agents/skills` | `.claude/skills` only |
| MCP config | `.mcp.json`, `~/.copilot/mcp-config.json`, cloud agent repository settings | `.mcp.json`, `~/.claude.json` |
| Permissions | Per-tool prompts, `--allow-tool` / `--deny-tool`, VS Code auto-approve rules, app Autopilot | default, acceptEdits, plan, auto, dontAsk, bypassPermissions |
| Enforcement | Tool rules, org MCP allow-list, cloud agent firewall | Hooks, managed settings |
| Subagents | Built-in (for example Explore, Task, Research, Code review) | Built-in (Explore, Plan) and custom subagents |
| Parallelism | App worktrees (preview), cloud agent sessions, delegation | Subagents, background agents |
| GitHub workflow | Native issue → PR, code review | `claude-code-action`; Claude inside GitHub via Agent HQ |
| Headless | `copilot -p`, cloud agent | `claude -p`, Agent SDK |
| Models | Multiple vendors, including Claude | Anthropic models, also via cloud providers including Microsoft Foundry |
| Admin plane | GitHub organization and enterprise | Claude managed settings and console |

## Boundaries that do not change

- Both run with the **developer's identity** locally; neither changes Fabric authorization.
- Both reach Fabric through the same execution paths: MCP servers, `az rest`, `fab` CLI, Git.
- Approval of Fabric changes stays in the accelerator's API or in pull-request review.

## Where each fits in the data-engineering lifecycle

| Step | Reasonable default | Alternative |
|---|---|---|
| Explore and triage (P19) | Copilot CLI + Fabric Skills | Claude Code with the same skills |
| Repo-first change (P20) | VS Code agent mode or cloud agent PR | Claude Code in the IDE, PR by hand |
| Headless review (P23) | `copilot -p` in GitHub Actions | `claude -p` / `claude-code-action`, any CI |

## Trade-offs

- **Model versus harness.** Copilot can run Claude models, so a bake-off must separate the model
  from the harness, or it measures the wrong thing.
- **Governance location.** One admin plane is simpler; two give flexibility at an operational
  cost.
- **Preview exposure.** Copilot app features are preview; keep them out of the default path.

## Online and offline

Both harnesses need network access to their model provider. The accelerator's MCP tools,
synthetic data and scorecard checks run offline; recorded replays of both harnesses arrive with
the bake-off in Phase 7.
