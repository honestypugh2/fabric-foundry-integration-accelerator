## Where enforcement actually happens

| Layer | GitHub Copilot | Claude Code |
|---|---|---|
| Model guidance | Instructions, `AGENTS.md`, skills | `CLAUDE.md`, imported `AGENTS.md`, skills |
| Harness gate | Per-tool approval; allow and deny rules; plan mode | Permission modes; plan mode blocks edits and shell until accepted |
| Programmable block | Deny rules; hooks in the Copilot SDK (verify hook support for your CLI version) | Hooks run before tool calls and can block them |
| Organization policy | MCP allow-list via enterprise managed settings; cloud agent firewall | Managed settings take precedence over project and user settings |
| Platform authority | Entra identity, Fabric roles, branch protection | Same |

Instructions and skills are **context, not enforcement** in both. Design so that a model that
ignores every instruction still cannot write to Fabric.

## Failure modes to test

- **Instruction precedence.** If `CLAUDE.md` exists without the `@AGENTS.md` import, Claude Code
  silently drops the shared rules. CI should check the import.
- **Conflicting layers.** Copilot supplies personal, repository and organization instructions
  together; conflicts are not resolved deterministically. Keep one rulebook.
- **Cloud agent autonomy.** Once MCP servers are configured for the Copilot cloud agent they run
  without per-call approval, and its firewall does not restrict MCP processes. Only read-only or
  offline tools belong there.
- **Bypass modes.** `bypassPermissions` and Autopilot remove the human gate; allowed only inside a
  sandbox with synthetic data.
- **Skill bundles.** The Skills for Fabric MCP configuration allows all tools on write-capable
  servers in either harness; the hardening applies to both: replace it with
  `ffia mcp render fabric-readonly --client vscode|claude|copilot-cli` and keep
  `fabric-authoring-gated` as a separate opt-in profile.
- **Token reuse.** Remote Fabric MCP needs an Entra token; verify the identity and tenant first.

## Threats to a fair comparison

| Threat | Mitigation |
|---|---|
| Model confounded with harness | Same model family where possible; record both |
| Nondeterminism | Several runs; report spread, not best case |
| Learner bias | Fixed prompts; blind scoring of outputs where practical |
| Version drift | Record harness, skills and MCP versions with the date |

## Production gaps

- The bake-off harness, replay fixtures and CI checks for the `@AGENTS.md` import arrive in
  Phase 7; security CI arrives in Phase 8.
- Organizations using both tools must operate two admin planes and keep their MCP allow-lists
  aligned by process, because nothing synchronizes them.
- Verify hook mechanics and sandboxing guidance against current vendor documentation before
  relying on them in production.
