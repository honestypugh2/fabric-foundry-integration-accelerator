## What is configured in this repo today

The root `.mcp.json` is shared by VS Code, Copilot CLI and Claude Code. It registers exactly two
servers:

- `microsoft-learn` - remote documentation search (read-only).
- `ffia-local` - this accelerator's LOCAL educational server, started with
  `uv run --frozen ffia serve mcp` over stdio.

**Neither is a Fabric MCP server.** Fabric MCP profiles (`offline.json`, `live-readonly.json`,
`live-authoring.json`, `fabric-skills.hardened.json` under `config/mcp/`) arrive in Phase 5 with
pinned versions such as `@microsoft/fabric-mcp@1.4.0` and `@microsoft/powerbi-modeling-mcp@1.0.0`.

## Inspect the local server

```bash
make run-mcp                         # or: ffia serve mcp (stdio; logs go to stderr)
cat config/policies/tools.yaml       # the allow-list: one entry per tool
ffia demo offline                    # act 3 makes a real MCP call to ffia-local
```

Each manifest entry declares `read_only`, `allowed_operations`, `rate_limit_per_minute`,
`timeout_seconds`, `audit` and `enabled`. A tool that is enabled but not implemented stops the
server at startup. There is no approve, execute, shell, SQL, filesystem or URL-fetch tool.

## Call it from a coding agent

```text
Use ffia-local: inspect_medallion_architecture(profile="hc-lab-7file-v1"),
then preview_table(profile="hc-lab-7file-v1", table="gold_financial", limit=5).
```

Read the envelope: `execution_label: LOCAL`, `cloud_operation_performed: false`,
`equivalent_fabric_service` and `simulation_notice`. The `equivalent_fabric_service` field tells
you which Fabric capability the answer stands in for - it is not a claim that Fabric ran.

## Mapping offline tools to Fabric servers

| ffia-local tool | Fabric server you would use live |
|---|---|
| `inspect_medallion_architecture`, `preview_table` | Local server `onelake_*` read tools |
| `evaluate_measures` | Fabric IQ MCP (DAX query) |
| `detect_duplicate_records` | A reviewed, read-only SQL query - not an arbitrary T-SQL tool |
| `generate_fabric_change_plan` | No MCP write; Git/PR or the approved change flow |

## Tests

`tests/unit/test_mcp_server.py` checks that only manifest tools are exposed and none can
authorize, that disabled tools are not registered, that a missing implementation fails fast,
that rate limits are enforced, and that the plan tool proposes but never executes. Try the
allow-list yourself in `lab-mcp-allow-list`.
