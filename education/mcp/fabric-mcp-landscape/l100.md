## What an MCP server is

The Model Context Protocol (MCP) lets an AI client - GitHub Copilot, Claude Code, a Foundry
agent - discover a server's **tools** and call them. A tool is a named operation with typed
inputs, such as "list files in a lakehouse" or "run this DAX query".

```text
 AI client ──"what tools do you have?"──▶ MCP server
 AI client ◀── list of tools + schemas ──
 AI client ──call tool(arguments)───────▶ MCP server ──▶ Fabric (as YOU)
 AI client ◀── result ───────────────────
```

The server acts **as you**: it uses your Entra sign-in and your Fabric permissions. It cannot
give you rights you do not have, and it does not stop you using rights you do have.

## Local vs remote

- **Local** servers run on your machine as a child process (stdio). Example: the Fabric MCP
  Server (local) and the Power BI Authoring MCP server (local).
- **Remote** servers are hosted by Microsoft and reached over HTTP with a token. Examples:
  Fabric IQ MCP, Data Warehouse MCP and Ontology MCP.

## Which server for which job

| I want to… | Use | Notes |
|---|---|---|
| Learn the right API or item format | Local server `docs_*` tools | Works offline |
| Browse lakehouse files and tables | Local server `onelake_*` tools | Some tools can upload or delete |
| Ask a semantic model a question | Fabric IQ MCP | Read-only, GA |
| Edit relationships or measures | Power BI Authoring MCP | Writes; local is GA |
| Run T-SQL | Data Warehouse MCP | PREVIEW; can run any SQL you are allowed to |
| Query business concepts | Ontology MCP | PREVIEW |

## Do not conflate servers

"It worked through Fabric MCP" is not precise enough. Always name the **server**, the **tool**
and the **identity** used. Two servers can expose similar-sounding tools with very different
permissions.

## Glossary

- **Tool:** one callable operation on a server.
- **Allow-list:** the tools you have chosen to permit, instead of everything offered.
- **ffia-local:** the accelerator's offline teaching server. It is not a Fabric MCP server.
