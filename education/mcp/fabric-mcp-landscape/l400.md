## Protocol behavior that affects governance

- **Discovery is not consent.** `tools/list` returns everything a server offers. A client that
  auto-approves discovered tools has delegated its policy to the server author. Allow-list per
  profile instead of `tools: ["*"]`.
- **Authorization is OAuth.** Remote MCP servers are OAuth resource servers. They must validate
  the token audience; tokens must not be passed through to other services. Some Fabric
  endpoints do not support dynamic client registration, so clients need pre-registered
  configuration.
- **Version negotiation.** The current MCP specification changed how protocol versions are
  negotiated while staying backward compatible. Pin server and SDK versions and re-test on
  upgrade.
- **Long-running work.** Some Fabric endpoints support the MCP tasks extension for
  long-running calls; clients that do not support it see a different interaction pattern.

## Failure modes

| Failure | Symptom | Control |
|---|---|---|
| Wrong tenant | Local server reads a different tenant than intended | Pin `az login --tenant`; verify the tenant with a read before any write |
| Server confusion | "Fabric MCP did it" with no server named | Record provider, server, tool and identity for every call |
| Arbitrary SQL | A "query" becomes `DROP` or `UPDATE` | Keep Data Warehouse MCP off by default; item-scoped endpoint; read-only SQL role |
| Hidden writes | `onelake_delete-file`, `datafactory_run-pipeline` enabled in a read profile | Explicit allow-lists; separate authoring profile |
| Preview drift | Endpoint or tool names change | Feature flags; tenant validation before each release |
| Silent substitution | A tool fails and the agent switches to REST or CLI | Rule: report the limitation and stop |

## Threat model

- **Prompt injection through tool results** (file contents, descriptions, query results) can
  ask the agent to call a write tool. Mitigation: no write tools on read paths; approval out of
  band.
- **Tool poisoning** - a malicious or changed tool description. Mitigation: pinned versions,
  reviewed manifests, gateways that log tool metadata.
- **Exfiltration** - results flow to the client's model and logs. Mitigation: least-privilege
  identity, RLS/OLS, and clients approved for the data classification.

## How ffia-local enforces its narrow surface

Tool annotations report `openWorldHint=false`; each call is rate limited per tool and audited;
arguments are checked against the catalog; stdio carries protocol traffic only. These
properties are **SIMULATED LOCALLY** and tested - they do not prove anything about a Fabric
server's behavior.
