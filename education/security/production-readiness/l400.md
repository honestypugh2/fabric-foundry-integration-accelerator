## Production design review

Start from the [threat model](../../../docs/security/threat-model.md) and assign owners to every
trust boundary. Assume prompts, retrieved documents and tool outputs can be adversarial.
Separate reasoning identity, governed read identity, authenticated approval identity and writer
identity. Bind approval to a canonical plan hash, permitted scope, authenticated approver and
expiry; validate again at execution. MCP capability discovery never confers authorization.

The educational API is not an authenticated production control plane. Before network exposure,
add appropriate authentication/authorization, TLS, gateway protections and session/CSRF defenses.
Replace local JSONL with protected durable audit. Treat hooks as defense in depth; use genuine
process/network isolation where untrusted code can execute.

## Evidence and supply-chain acceptance

Test non-admin positive/negative access, RLS/OLS propagation, indirect injection, replay/expiry,
duplicate writes, dependency changes and failure recovery. Preserve synthetic evaluation baselines
while adding representative tenant-specific tests. A CodeQL upload is not a zero-alert certificate;
protect branches and triage findings. Review SBOM scope, licenses and checksum verification;
sign provenance if production policy requires it.

## Operational and financial gates

Bound concurrency, retries and tool scope; configure alerts for model/tool use, latency, failures
and cost. Budgets are alerts, not hard stop guarantees. Ingestion caps cover one dimension,
not the full bill. Approve a capacity operating schedule and a stop/rollback owner.

Client telemetry ingestion was observed on 2026-10-09; new server-side agent tracing remains
unverified and needs an approved run. The recorded live agent evaluation and held draft are
dated demo evidence, not certification. Keep Claude Code documented-only until actual runs exist.
Do not turn an unavailable live write into a simulated success.
