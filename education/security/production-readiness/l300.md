## Code-first release walkthrough

Make a focused branch change to synthetic configuration or structured education. Add tests for
changed behavior, regenerate only related outputs (`ffia prompts render`, `ffia sources render`
or schema/diagram/fixture commands as appropriate) and review the exact diff.
Run `make validate` and `make sbom` in the activated virtual environment.

The validation chain covers strict Python/TypeScript, formatting, tests with coverage, synthetic
data reproducibility, privacy, builds, dependency audits and generated-content drift.
Agent evaluation enforces 100% of five baseline cases. It checks numbers, expected grounding and
out-of-scope behavior; a fallback cannot count as success for the requested provider.

## CI boundaries

Actions are pinned to commit SHAs. Checkout does not persist credentials. CI defaults to offline
providers and has no Azure secrets. CodeQL analyzes Python and JavaScript/TypeScript on push/PR
and weekly; only analysis jobs need security-events write.
Release artifact creation waits for quality and CodeQL, then produces distributions, a frontend
archive, CycloneDX SBOMs and checksums. It has no publication/deployment authority.

## Threat and cost testing

Read `tests/unit/test_mcp_server.py` for tool exposure/rate limits, `test_harness.py` for denied
commands, `test_tracing.py` for question-text exclusion and `test_agent_eval.py` for wrong-answer
and fallback rejection. Client guards are not process isolation.

Use bounded retries/timeouts, serialization for live Fabric agent calls, quota and budget alerts.
Test outages and exact-cent workflow holds. Delivery remains a separately approved transactional
write; do not automatically "fix" underlying data or send a brief because the draft looks fluent.
