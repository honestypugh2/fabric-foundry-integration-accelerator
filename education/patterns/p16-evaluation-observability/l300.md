## Run the baseline evaluation

```bash
make run-api        # control plane on 127.0.0.1:8000
curl -s -X POST localhost:8000/api/v1/evaluations/run \
  -H 'Content-Type: application/json' \
  -H 'X-Correlation-ID: 0123456789abcdef0123456789abcdef' \
  -d '{"profile": "hc-lab-7file-v1"}' | python -m json.tool
```

Read `data.compared`, `data.passed`, `data.pass_rate`, `data.gate_passed`,
`data.observed_values_source` (`local-provider`) and the envelope's `execution_label` (`LOCAL`).
For the Use-Case Guide profile all 23 measures should pass.

Now submit values yourself, as you would after running DAX in a tenant:

```bash
curl -s -X POST localhost:8000/api/v1/evaluations/run -H 'Content-Type: application/json' \
  -d '{"profile": "hc-lab-7file-v1", "observed": {"claim_count": 1}, "observed_label": "LIVE"}'
```

The result is `caller-supplied`, its evidence is `REQUIRES TENANT VALIDATION`, the wrong value
fails, and `missing_measures` lists everything you did not supply.

## Evaluate and trace the agent

```bash
ffia agents eval        # config/evaluations/sales-insights-agent.yaml, 5 cases, min_pass_rate 1.0
curl -s -X POST localhost:8000/api/v1/agents/evaluate
```

Each case checks `grounded` (a governed data tool produced the numbers) and that the expected
baseline values appear in the answer, ignoring `$` and thousands separators. Offline the agent is
`LocalSalesAgent`, labeled `LOCAL`. Every routed ask also emits an OpenTelemetry span
`ffia.agent.ask` with `correlation_id`, `provider`, `execution_label`, `fallback_used`, `tools`,
`grounded`, `agent` and `question_length` - never the question text. Export to Application
Insights happens only when `FFIA_APPLICATIONINSIGHTS_CONNECTION_STRING` is set (a secret; keep it
in a git-ignored `.env`).

## Follow the evidence

```bash
curl -s localhost:8000/api/v1/audit/0123456789abcdef0123456789abcdef | python -m json.tool
```

Each `AuditRecord` has `actor`, `action` (for example `read:evaluate_measures`), `capability`,
`requested_provider`, `selected_provider`, `operating_mode`, `execution_label`,
`cloud_operation_performed`, `fallback_used`, `fallback_reason` and `duration_ms`.

## Through MCP

On `ffia-local`: `evaluate_measures`, `evaluate_against_baseline` and `get_audit_record`
(redacted). There is no tool to edit a baseline or a threshold.

## Configure the gate

```yaml
# config/customers/example-healthcare.yaml
evaluation_thresholds:
  measure_absolute_tolerance: 0.000001
  minimum_pass_rate: 1.0
```

|---|---|
| `services/evaluation.py` | `compare`, `EvaluationService.run`, provenance labels |
