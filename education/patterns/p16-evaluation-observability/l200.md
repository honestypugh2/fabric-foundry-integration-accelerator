## Components and boundaries

| Component | Responsibility | Must not |
|---|---|---|
| Expected baseline (`data/synthetic/expected/`) | The agreed values for every measure | Be regenerated to hide a regression |
| Baseline evaluator (`EvaluationService`) | Compare observed values within tolerance; compute the gate | Claim it retrieved caller-supplied values |
| Overlay `evaluation_thresholds` | Tolerance and minimum pass rate per customer overlay | Be loosened without review |
| Foundry evaluators | Score groundedness, relevance, tool use, safety | Replace deterministic checks for numbers |
| Audit store | Append redacted records per correlation ID | Hold tokens, secrets or raw PII |
| Execution envelope | Carry label, providers, fallback and evidence | Contradict what ran (validated in code) |
| Tracing (Phase 6) | Spans across agent, tools and providers | Export sensitive prompt content unredacted |

## Data flow

1. Middleware assigns or accepts a 32-hex `X-Correlation-ID` and binds it to logs.
2. The router or service produces an **execution envelope** with labels and evidence.
3. The router writes an **audit record** for each routed read, including fallbacks and
   `UNAVAILABLE` outcomes.
4. `POST /api/v1/evaluations/run` compares measures and returns `gate_passed`.
5. `GET /api/v1/audit/{correlation_id}` reconstructs what happened.

## Where the observed values come from

| Source | `observed_values_source` | Evidence category |
|---|---|---|
| Local provider (no `observed` in the request) | `local-provider` | SIMULATED LOCALLY |
| Values a person copied from a live DAX query | `caller-supplied` | REQUIRES TENANT VALIDATION |

The evaluator is honest about provenance: supplying values labeled `LIVE` does not make the
accelerator a witness to a live run.

## Trade-offs

- **Deterministic gates** are cheap, exact and explainable, but only cover what you can compute.
- **Model-graded evaluators** cover language quality, but cost tokens, vary between runs and need
  calibration. Preview evaluators should inform rather than solely gate a release.
- **Tracing everything** helps diagnosis but increases data volume and redaction obligations.

## Online and offline

Offline, every evaluation and audit record is `LOCAL`. In `HYBRID`, the same records show
`fallback_used` and the reason. Live Foundry evaluations and traces arrive in Phase 6.
