## What it is

**Evaluation** checks quality. **Observability** shows what happened. Together they let you trust
an agent that works with business data.

```text
request ──► API ──► router ──► provider ──► result
   │          │         │           │          │
   └──────────┴─────────┴───────────┴──────────┴──► same correlation ID
                                                    │
                                     audit record + execution label
                                                    │
                                     evaluation: baseline gate (numbers)
                                                 evaluators (answers)
```

## Two kinds of evaluation

- **Deterministic (numbers):** "Is *Claim Count* exactly what we expect?" A program compares the
  value with a committed **expected baseline**. No model is involved, so the verdict is the same
  every time.
- **Model-graded (language):** "Is this answer grounded in the data? Did the agent call the right
  tool?" A model scores the output. Foundry provides built-in evaluators for this.

Use the first for anything you can compute. Use the second for things only language judgment can
assess.

## Observability basics

- **Correlation ID:** one ID per request, returned in the `X-Correlation-ID` header.
- **Audit record:** who asked, which provider ran, the label, and whether a fallback happened.
- **Execution label:** the honest answer to "what actually ran?"
- **Traces:** timed spans for each step, using OpenTelemetry (added with agents in Phase 6).

## Key ideas

- A green demo is not proof; a passed gate with evidence is.
- Values copied in by a person are marked *caller-supplied*, not *retrieved*.
- In this repository, evaluation and audit run locally and are labeled `LOCAL`.
