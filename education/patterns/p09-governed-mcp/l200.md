## Components and boundaries

| Component | Responsibility | Must not |
|---|---|---|
| MCP client (VS Code, Copilot CLI, Claude Code, Foundry agent) | Discover and call tools; ask the user to confirm | Enable every tool by default |
| Client configuration (`.mcp.json`) | Which servers, pinned versions, which tools | Contain secrets or tenant identifiers |
| MCP server | Register allow-listed, typed tools; validate inputs | Proxy arbitrary shell, SQL, files, URLs or REST |
| Tool manifest | Owner, version, classification, limits, audit, revocation | Be bypassed by code that registers extra tools |
| Gateway (APIM, pattern P15) | Authentication, quotas, routing, telemetry | Replace backend authorization |
| Backend (Fabric, business API) | Enforce the caller's permissions | Trust that the tool call was authorized |
| Audit store | Record each call with a correlation ID | Store tokens or raw sensitive data |

## Identity paths

- **Local stdio servers** run as a process under the developer's account. `ffia-local` holds no
  cloud credentials at all; the local Fabric MCP server uses Azure CLI sign-in only for live
  operations.
- **Remote servers** (Fabric IQ MCP, data agent MCP, Data Warehouse MCP) use Entra OAuth and the
  caller's own Fabric permissions — no elevation.
- **Foundry agents** connect through project connections and can restrict `allowed_tools` and
  require approval per call.

## Choosing the narrowest server

| Need | Choose | Avoid |
|---|---|---|
| Learn an API or item format | Local Fabric MCP docs tools, Microsoft Learn MCP | A live, write-capable server |
| Inspect what exists | Read-only remote tools | A server that can also create items |
| Ask a business question | Fabric IQ MCP or a data agent | Free-form SQL |
| Change something | P08 plan → approval → scoped writer | A create/delete tool called by the model |

## Trade-offs

- **Many small typed tools** are safer and easier to evaluate, but need more design than one
  generic "query" tool.
- **A gateway** centralizes policy and telemetry but adds latency and cost; it pays off when many
  consumers share tools.
- **Bundled skill configurations** are convenient but may enable every tool (`"*"`) on
  write-capable servers; replace them with a rendered read-only profile
  (`ffia mcp render fabric-readonly`).

## Online and offline

Offline, `ffia-local` provides the real protocol with synthetic data (`LOCAL`). Online, the same
clients connect to pinned Fabric MCP profiles from `config/mcp/profiles.yaml` (`fabric-docs`,
`fabric-readonly`), each read-only unless an opt-in,
approval-gated authoring profile is chosen.
