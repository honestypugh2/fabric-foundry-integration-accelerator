## The manifest decides what exists

`config/policies/tools.yaml` is the allow-list for `ffia-local`. Each entry carries governance
metadata, for example:

```yaml
- name: preview_table
  owner: accelerator-maintainers
  version: 1.0.0
  classification: synthetic-data
  allowed_operations: [read]
  read_only: true
  rate_limit_per_minute: 60
  timeout_seconds: 15
  audit: true
  enabled: true
  revocation: 'Set enabled: false in config/policies/tools.yaml and restart the server.'
```

Only `read` and `propose` operations are valid in the schema. The two `propose` tools
(`generate_fabric_change_plan`, `validate_change_plan`) create or re-check a **plan**; nothing
can approve or execute it over MCP.

## How a tool becomes callable

In `src/fabric_foundry_accelerator/mcp/server.py`, `build_mcp_server`:

1. Loads the manifest and the Python implementations.
2. **Fails fast** with `manifest enables tools without an implementation` if an enabled entry
   has no code — a typo cannot silently create or hide a tool.
3. Registers each *enabled* tool, wrapped by `_governed`: a sliding one-minute **rate limiter**,
   error translation to `ToolError`, and an **audit record** (`action: mcp:<tool>`).
4. Sets **annotations** from the manifest: `readOnlyHint` and `idempotentHint` from `read_only`,
   `destructiveHint: false`, `openWorldHint: false`, and the classification as a tag.

Inputs are bounded: `preview_table` returns at most 20 rows, profiles and tables must exist in
the catalog, and SQL identifiers are quoted internally — there is no free-form SQL or DAX.

## Run it

```bash
make run-mcp            # or: ffia serve mcp (stdio; logs go to stderr)
ffia demo offline       # act 3 makes a real MCP call to inspect_medallion_architecture
```

`.mcp.json` registers `ffia-local` (via `uv run --frozen ffia serve mcp`) next to the Microsoft
Learn server, so VS Code, Copilot CLI and Claude Code share it. Each result is an execution
envelope: `execution_label: LOCAL`, `cloud_operation_performed: false` and a `correlation_id`
you can pass to `get_audit_record`.

## What the tests prove

`tests/unit/test_mcp_server.py` covers: only manifest tools are exposed and none can authorize;
disabled tools are not registered; manifest entries without an implementation fail fast; rate
limits are enforced through the server; results are honestly labeled; the plan tool never
executes; and tool errors are reported and audited.

Practice this in **lab-mcp-allow-list**.
