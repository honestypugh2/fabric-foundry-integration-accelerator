## Build the medallion locally

```bash
source .venv/bin/activate
ffia data generate --check   # committed raw CSVs equal the seeded generator output
ffia data build              # Bronze -> Silver -> Gold Parquet, all checks, baseline comparison
ffia data build --verbose    # print every individual check
```

Expected summary for the Use-Case Guide profile:

```text
hc-lab-7file-v1: 24 tables (bronze 7, silver 7, gold 10); 58/58 checks passed; baseline matched [LOCAL, no cloud operation]
```

## Where the logic lives

| Path | What it holds |
|---|---|
| `data/synthetic/raw/<profile>/` | Source CSVs and `manifest.json` (rows, SHA-256, injected quirks) |
| `src/fabric_foundry_accelerator/synthetic/sql/silver/*.sql` | One `SELECT` per Silver table, e.g. `silver_encounters.sql` |
| `src/fabric_foundry_accelerator/synthetic/sql/gold_shared/`, `gold_hc_lab/` | Gold facts and dimensions |
| `data/synthetic/semantic/<profile>/semantic-model.yaml` | Tables, relationships, measures as local `sql` plus reference `dax` |
| `data/synthetic/expected/<profile>.json` | Row counts, diagnostics, reconciliation totals and every measure |

The builder wraps each SQL file in `CREATE TABLE … AS`. Silver diagnostics must detect the
injected quirks **exactly** (for example 4 length-of-stay mismatches and 5 blank charges).

## Inspect through MCP

Start `ffia serve mcp` (or use the `.mcp.json` entry) and call, on `ffia-local`:

- `inspect_medallion_architecture` with `profile: hc-lab-7file-v1` → tables and row counts per layer
- `preview_table` with `profile` and `table: silver_encounters` → at most 20 rows, labeled `LOCAL`
- `evaluate_measures` → every declared measure
- `evaluate_against_baseline` → pass/fail per measure

There is no SQL tool: reads are typed and bounded.

## Prove the numbers over REST

```bash
curl -s -X POST localhost:8000/api/v1/evaluations/run \
  -H 'Content-Type: application/json' -d '{"profile": "hc-lab-7file-v1"}'
```

The result reports `compared`, `passed`, `pass_rate` and `gate_passed`, with
`observed_values_source: local-provider`.

## Tests

`tests/unit/test_medallion.py`, `test_measures.py` and `test_semantic_model.py` cover layer
builds, quirk detection and measure values; `tests/offline/test_offline_data_path.py` runs the
path end to end.
