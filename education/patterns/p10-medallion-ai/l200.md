## Components and boundaries

| Component | Responsibility | Must not |
|---|---|---|
| Bronze lakehouse | Land sources as-is with load metadata | Be queried for business answers |
| Silver transformations | Typing, conformance, quality flags, diagnostics | Silently drop or "fix" source facts |
| Gold tables | Facts and dimensions at a declared grain | Mix grains in one table |
| Semantic model | Relationships, measures, synonyms, descriptions | Re-implement Gold logic in DAX |
| AI assistance (Copilot, Claude Code, AI functions) | Draft, profile, explain, enrich | Approve its own output |
| Tests and expected baseline | Decide correctness | Be regenerated to match a broken build |

## Data flow and identity

- Engineers (or pipelines under a workspace identity) write Bronze → Silver → Gold.
- Agents and report users get **read** access to Gold and the semantic model only. Layer
  separation is enforced with workspace or item permissions, not with prompts.
- A Foundry agent reaches Gold through a semantic model or a Fabric data agent, so the governed
  definitions and the caller's permissions apply.

## Direct Lake trade-offs

| Option | Benefit | Watch for |
|---|---|---|
| Direct Lake on OneLake | No import copy; recommended for new models | No DirectQuery fallback |
| Direct Lake on the SQL analytics endpoint | Single SQL source | Fallback to DirectQuery can be automatic; SQL-level security can trigger it |
| Import | Predictable performance | A second copy to refresh and govern |

## Where deterministic logic must decide

- **Grain and keys:** declared per Gold table; duplicates fail the build.
- **Measure math:** e.g. a ratio of totals, never an average of grouped averages.
- **Quality rules:** range and chronology checks *report* issues; they never label a clinical
  condition.
- **Release gate:** every measure equals its expected value within tolerance.
