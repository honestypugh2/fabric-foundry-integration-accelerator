## What it is

A **governed action** is any change an agent wants to make to a business system or a Fabric item.
Instead of letting the agent call a "create" tool directly, the change goes through six steps:

```text
PLAN → VALIDATE → APPROVE → EXECUTE → VERIFY → AUDIT
```

- **Plan:** the agent describes the change. Nothing runs.
- **Validate:** rules check it — is the operation allowed, is the workspace known, does the item already exist?
- **Approve:** a different person says yes or no.
- **Execute:** a dedicated service performs exactly the approved change.
- **Verify:** the system checks the result.
- **Audit:** every step is recorded with a correlation ID.

## Key ideas

- **The model proposes; it never authorizes.** An agent asking to do something is not proof that
  the user is allowed to do it.
- **MCP is access, not authority.** A tool being available does not mean it may be used.
- **Simulation is labeled.** In offline mode, execution happens in a simulated workspace and the
  result says `SIMULATED`.
