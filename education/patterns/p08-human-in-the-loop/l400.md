## Enforcement details

- **Policy evaluation is deterministic.** `evaluate_write` returns `allowed`, `risk` and reasons
  from the policy file and overlay; `approval_required` is always true for writes.
- **Preconditions.** For create operations the plan records whether the item already exists; a
  duplicate makes the plan `BLOCKED`. For LIVE targets the precondition is recorded as
  `REQUIRES TENANT VALIDATION` because no live provider has checked it.
- **Destination binding.** The plan stores `destination_hash` (target + destination). Execution
  recomputes it and refuses a mismatch, which defeats "approve one thing, execute another".
- **Approval lifecycle.** Approvals expire after `approval_ttl_minutes`; rejected approvals mark
  the plan `REJECTED`; an executed plan cannot be executed again (409).
- **No silent redirect.** `LiveWriteUnavailableError` is raised for approved LIVE plans until an
  authorized writer exists; the simulated workspace is untouched, and the offline demo asserts it.

## Threats this addresses

| Threat | Control |
|---|---|
| Prompt injection asks the agent to write | No write tool over MCP; approval is out-of-band |
| Agent approves its own plan | Separation of duties |
| Approval reused for another target | Destination hash |
| Race between approval and execution | Precondition re-check at execution |
| Fake success from a simulation | Labels + LIVE never redirected |
| Missing evidence | Audit record per step under one correlation ID |

## Production gaps to close

A real writer needs an Entra identity scoped to the target workspace, exact item IDs (not names),
a post-write read from the system of record, and an append-only audit sink outside the app.
