## Components and responsibilities

| Component | Responsibility | Must not |
|---|---|---|
| Client app or Copilot surface | Sign the user in, show answers, labels and approvals | Hold Fabric or Foundry secrets in the browser |
| Foundry agent (Agent Service or Agent Framework) | Reason, call tools, cite, propose | Approve or perform authoritative writes |
| Fabric data agent / semantic model / lakehouse | Answer from governed data with the caller's permissions | Be bypassed with ad-hoc SQL over raw files |
| Foundry IQ knowledge (optional) | Unstructured documents with citations | Replace the semantic model for numbers |
| MCP servers and tool connections | Standard, allow-listed access | Grant authority |
| Entra ID and policy | Who may read, propose, approve and write | Be inferred from model intent |
| Change service, approver, scoped writer (P08) | Plan, approve, execute, verify | Accept self-approval |
| Evaluation, tracing, audit | Prove quality and what ran | Store tokens or PHI |

## Identity paths

1. **User → agent:** the user signs in; the app passes the user context to the agent.
2. **Agent → Fabric (read):** identity passthrough (on-behalf-of) so row-level security applies.
   The preview Foundry Fabric tool supports user identity only, not service principals.
3. **Agent → tools:** the agent's own Entra identity, limited by an allow-list and approval
   settings on each MCP tool.
4. **Approver → change service:** a different human identity (separation of duties).
5. **Scoped writer → business system:** a separate least-privilege identity.

## Data flow

Question → agent plans → governed read (semantic model or data agent) → grounded answer with
citations → optional proposed action → approval → scoped write → verification → audit, all
joined by one correlation ID.

## Trade-offs

- **Data agent vs. direct semantic model queries:** a data agent adds Fabric-side instructions
  and examples; a direct query is more predictable and fully GA.
- **Prompt agent vs. hosted Agent Framework agent:** prompt agents are fully managed; hosted
  agents give code-level control over workflows and checkpoints.
- **Preview tools:** faster integration, but preview SLAs and identity limits.
