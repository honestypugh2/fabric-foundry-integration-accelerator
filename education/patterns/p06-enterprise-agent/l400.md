## Enforcement points end to end

| Hop | Control | Failure mode if missing |
|---|---|---|
| User → agent | Entra sign-in; user context forwarded | Agent answers as a shared identity and leaks data |
| Agent → Fabric | On-behalf-of passthrough; RLS/OLS in the semantic model | Over-broad reads; numbers differ by caller unexpectedly |
| Agent → MCP tools | `allowed_tools`, approval required for state changes, pinned server versions | Prompt injection drives an unintended tool |
| Tool output → agent | Treat as untrusted data, never as instructions | Indirect prompt injection from a table or document |
| Proposal → change | P08 plan, separation of duties, destination hash, expiry | "Approve one thing, execute another" |
| Change → system | Scoped writer, precondition re-check, post-write verification | Duplicate or partial writes |
| Everything | Correlation ID across audit, traces and evaluations | No way to prove what happened |

## Resilience

The agent consumes provider results, not raw cloud calls. The router applies a per-capability
timeout, bounded retries with jitter and a circuit breaker (3 failures → `OPEN`, 60 s →
`HALF_OPEN`). Reads may fall back to local data **only** when policy allows, and the envelope then
says `operating_mode: HYBRID`, `fallback_used: true` and why; writes never fall back, and an approved LIVE write that cannot
run returns `UNAVAILABLE`. An agent must surface these labels to the user instead of
paraphrasing them away.

## Evaluation as a release gate

Score groundedness, relevance and tool call accuracy (GA) plus task adherence (preview) on a
fixed synthetic question set, and fail the release when scores regress. Locally, the
deterministic analogue is the baseline comparison (`POST /api/v1/evaluations/run`), which is the
offline demo's data gate.

## Threat model highlights

- **Confused deputy:** an agent identity with broad Fabric rights answering for many users.
  Mitigate with passthrough and a read-only agent identity.
- **Preview identity limits:** the Foundry Fabric data agent tool does not support service
  principals, so unattended jobs need a different, GA path.
- **Data residency:** answers returned through an external client may leave the Fabric
  compliance boundary; review which clients may connect.
- **Simulation mistaken for reality:** prevented by labels and by never redirecting LIVE writes.

## Production gaps to close

A real deployment needs tenant validation of passthrough and RLS with real roles, private
networking per the baseline Foundry chat architecture, trace retention, an evaluation dataset
owned by the business, and an append-only audit sink outside the application.
