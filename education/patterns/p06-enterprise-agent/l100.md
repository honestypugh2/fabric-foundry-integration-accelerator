## What it is

An **enterprise agent** is an application assistant that answers business questions and can
propose actions. P06 shows how the pieces fit together:

```text
 User question
      │
      ▼
 Foundry agent ── reasons, plans, calls tools, is evaluated and traced
      │  (MCP and other tool connections = ACCESS)
      ▼
 Fabric context ── Gold tables, semantic model, data agent (GOVERNED DATA)
      │
      ▼
 Answer with citations ── or a PROPOSED action
      │
      ▼
 Human approval (P08) ── Entra identity and policy = AUTHORITY
      │
      ▼
 Scoped writer changes the business system ── audit = EVIDENCE
```

## Why it is built this way

- **Fabric is the source of truth for context.** Business definitions (for example how the
  synthetic `denial_rate` measure is calculated) live in the semantic model, not in a prompt.
- **Foundry is where reasoning happens.** The agent decides which question to ask Fabric and how
  to combine answers, and its quality is measured by evaluators.
- **MCP is a plug, not a key.** It gives the agent a standard way to reach tools. It does not
  decide whether the agent is allowed to use them.
- **Identity is the key.** The agent reads Fabric as the signed-in user, so people only see what
  they are already allowed to see.
- **Actions are proposals.** The agent drafts a change; a person approves it; a narrow service
  performs it.

## Key words

- **Governed context** — certified data with security and definitions attached.
- **Grounded answer** — an answer that can be traced back to the data it used.
- **Execution label** — every result says whether it was `LIVE`, `LOCAL`, `SIMULATED` or
  `UNAVAILABLE`. In this repository, offline results are `LOCAL` or `SIMULATED`, and the Foundry
  step is `UNAVAILABLE` until Phase 6.
