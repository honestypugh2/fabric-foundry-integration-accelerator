## Check readiness and run the release gate

```bash
source .venv/bin/activate
ffia demo check --no-azure-cli      # status per component + recommended mode (--json available)
ffia demo offline                   # ten acts; must end with "Release gate: PASSED"
```

Act 7 builds a HYBRID router with `SimulatedOutageFabricProvider` and shows four reads falling
back, the breaker opening after three failures and the last read skipping the live call.

## Break it through the API

```bash
FFIA_ENVIRONMENT=hybrid FFIA_SIMULATE_FABRIC_OUTAGE=1 ffia serve api
```

In a second terminal:

```bash
curl -s localhost:8000/api/v1/runtime/providers | python -m json.tool
for i in 1 2 3 4; do
  curl -s -X POST localhost:8000/api/v1/fabric/read -H 'Content-Type: application/json' \
    -d '{"operation": "read_table", "lakehouse_id": "local-lh-hc-lab-7file-v1", "table": "gold_alos", "limit": 3}' \
    | python -m json.tool | grep -E '"(operating_mode|execution_label|fallback_used|fallback_reason)"'
done
curl -s localhost:8000/api/v1/runtime/status | python -m json.tool
```

What you should see:

- The providers list shows `Fabric REST API (simulated outage)` with kind `FAULT-INJECTION`,
  `ready: false`.
- Each read returns `operating_mode: HYBRID`, `execution_label: LOCAL`, `fallback_used: true`
  and a `fallback_reason`. On the fourth, the reason says `circuit breaker OPEN`.
- `runtime/status` shows the `fabric_data` breaker `OPEN` with `consecutive_failures: 3` and
  `recent_route_decisions` with outcome `FALLBACK` and `attempts: 2` (one call plus one retry).

Now send a client error: `"table": "no_such_table"` returns **404** with no fallback.

## Other read operations

`POST /api/v1/fabric/read` accepts a discriminated `operation`: `list_workspaces`, `list_items`
(`workspace_id`), `list_tables` (`lakehouse_id`), `read_table` (`lakehouse_id`, `table`, `limit`
≤ the preview cap), `get_semantic_model` and `evaluate_measures` (`semantic_model_id`). No
free-form query exists.

## LIVE mode

With `FFIA_ENVIRONMENT=live` and no live provider configured, the same read returns **503**
(`UNAVAILABLE`) because LIVE has no fallback.

## Tests

`tests/unit/test_router.py` covers breaker transitions, local-preferred routing, LIVE success and
audit, retry recovery, fallback with reason, client errors without fallback, timeouts and
`UNAVAILABLE`. `tests/offline/test_offline_demo.py` runs the release gate.
