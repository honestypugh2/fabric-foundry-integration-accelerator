## Components and boundaries

| Component | Responsibility | Must not |
|---|---|---|
| Environment config (`config/environments/*.yaml`) | Per-capability `preferred`, `fallback`, `timeout_seconds`, `max_retries`, `backoff_seconds`; breaker policy | Allow a fallback for writes |
| Fallback policy (`config/policies/fallback.yaml`) | Reads may fall back; writes never; client errors never | Be overridden by a customer overlay |
| `ProviderRouter` | Probe, timeout, retry, classify, fall back, record a `RouteDecision`, audit | Hide the requested provider |
| `CircuitBreaker` | CLOSED → OPEN → HALF_OPEN per capability | Count client errors as failures |
| `RoutedFabricProvider` | Exposes routed reads behind the Fabric provider port | Offer write operations |
| Change service | Governed writes (P08) | Use the router's fallback |
| Runtime API | Report providers, breakers and recent decisions | Imply a live connection that does not exist |

## Per-capability policy (HYBRID)

| Capability | Preferred | Fallback | Timeout | Retries |
|---|---|---|---|---|
| `fabric_data` | live | local | 5 s | 1 |
| `semantic_model` | live | local | 5 s | 1 |
| `mcp`, `evaluation`, `audit` | local | none | — | — |

The breaker policy is `failure_threshold: 3`, `reset_timeout_seconds: 60`.

## Outcomes and labels

| Outcome | Envelope | HTTP |
|---|---|---|
| LIVE success | Label `LIVE`, `cloud_operation_performed: true` | 200 |
| Fallback | Data from LOCAL, `operating_mode: HYBRID`, `fallback_used: true`, `fallback_reason` | 200 |
| No fallback allowed (for example in LIVE mode) | `CapabilityUnavailableError` | 503 → `UNAVAILABLE` |
| Client error (unknown table) | Error returned as-is | 404 / 422 |

## Identity paths

Fallback never changes *who* is asking. LOCAL equivalents run as the local process with no cloud
identity, so a fallback can never escalate access. The opt-in `LiveFabricProvider` uses the
signed-in caller's identity, and an authorization failure is reported, not routed around.

## Trade-offs

- **Fallback improves continuity** but serves synthetic data: acceptable in demos and workshops,
  usually not in production analytics. That is why it is a per-environment decision.
- **Aggressive retries** hide blips but amplify throttling; **tight timeouts** keep the UI
  responsive but can open the breaker on a merely slow service.
- **Per-process breakers** are simple; multiple instances each learn about an outage separately.
