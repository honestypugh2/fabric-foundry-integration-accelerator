## What it is

A **router** sits between the application and the services it depends on. For every read it asks:
*is the live service healthy, and if not, am I allowed to use the local equivalent?*

```text
read request
    │
    ▼
breaker OPEN? ── yes ──────────────────────────┐
    │ no                                        │
    ▼                                           ▼
call LIVE (timeout, retry with jitter)    fallback allowed?
    │ success → result labeled LIVE         │ yes → LOCAL data, mode HYBRID,
    │ client error → return the error        │       fallback_used + reason
    │ outage → count a failure ─────────────►│ no  → UNAVAILABLE (503)
```

## Glossary

- **Timeout:** the longest the router waits for one call (5 seconds for Fabric data in HYBRID).
- **Retry with jitter:** try again after a short, slightly random pause so many clients do not
  retry at the same instant.
- **Circuit breaker:** after **3** failed requests in a row it **opens** and stops calling the
  live service; after **60 seconds** it lets **one** trial call through.
- **Fallback:** serving a read from the approved local equivalent, clearly labeled.
- **Execution label:** the honest answer to "what ran?" — `LIVE`, `HYBRID`, `LOCAL`,
  `SIMULATED`, `MOCKED`, `PREVIEW` or `UNAVAILABLE`.

## Choosing a mode

Set `FFIA_ENVIRONMENT` to `offline`, `hybrid` or `live`. Run `ffia demo check` first; it probes
each component and recommends a mode.

## Key ideas

- A fallback is never silent.
- Only **reads** fall back. Changes go through the governed flow (P08) and never fall back.
- `ffia demo offline` proves the whole story works with no cloud at all.
