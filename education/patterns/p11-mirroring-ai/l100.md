## What it is

**Mirroring** copies a source database into OneLake and keeps it up to date. **Open Mirroring**
is the "bring your own publisher" version: your application writes files into a **landing zone**
and Fabric applies them to a Delta table.

```text
publisher ─► LandingZone/claims/
               _metadata.json            {"keyColumns": ["claim_id"]}
               00000000000000000001.parquet   initial load (all INSERT)
               00000000000000000002.parquet   changes with __rowMarker__
               ...
           ─► mirrored Delta table ─► Silver ─► Gold ─► agents
```

## The rules in plain words

- Every table folder has a `_metadata.json` that names the **key columns**.
- Files are numbered with **20 digits**, one after another, with no gaps.
- Each change row carries a `__rowMarker__` in the **last** column:
  - `0` INSERT — adds the row, **without checking for duplicates**
  - `1` UPDATE — changes the row (adds it if the key is missing)
  - `2` DELETE — removes the row (does nothing if the key is missing)
  - `4` UPSERT — insert or update
- Updates, deletes and upserts only work when keys are defined.
- After a file is processed, it is moved aside and **deleted after seven days**.

## Recovery in one sentence

Keep a **snapshot** (a full copy plus the last file number it includes), keep your **change
files**, and if the table is lost, **restore the snapshot and replay** the files that came after
it.

## Key ideas

- Fresh data is valuable context for AI, but freshness is not durability.
- Re-sending INSERT rows creates duplicates; UPSERT does not.
- Results from this repository's drill are labeled `SIMULATED`.
