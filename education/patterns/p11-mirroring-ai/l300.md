## Run the drill

```bash
source .venv/bin/activate
ffia recovery run          # or: make recovery-demo
```

The scenario lives in `data/synthetic/recovery/scenario.yaml`: the `claims` table of profile
`hc-lab-7file-v1`, `key_columns: [claim_id]`, `retention_days: 7`, `snapshot_day: 7`,
`failure_day: 10`. Expect lines such as:

```text
[DOCUMENTED FABRIC BEHAVIOR] Day 5 incremental (day 5): ... source re-sent yesterday's inserts as INSERT; 1043 rows, 2 duplicated keys
[PRODUCTION RECOMMENDATION] Weekly full snapshot (day 7): Snapshot claims-day007-seq00008 ...
    PASS Recovered content hash equals pre-failure hash: match
    FAIL Change files after watermark 1 are contiguous: missing sequences [2, 3, 4]
Recovered from weekly snapshot: YES
Recoverable without the weekly snapshot: NO
```

The FAIL lines are intentional: they are the counterfactual and the idempotency lesson.

## Inspect the artifacts

```bash
ls data/synthetic/recovery/runs/latest/landing/LandingZone/claims
cat data/synthetic/recovery/runs/latest/landing/LandingZone/claims/_metadata.json
ls data/synthetic/recovery/runs/latest/snapshots
```

Snapshots are Parquet files with a JSON manifest (`claims-day007-seq00008.json`) holding the
watermark sequence, row count and content hash.

## Where the code lives

| Module | Role |
|---|---|
| `recovery/open_mirroring.py` | `RowMarker`, `landing_file_name`, `apply_changes`, `LandingZoneTable` |
| `recovery/snapshots.py` | `create_snapshot`, `restore_snapshot`, `replay_changes`, `detect_duplicates`, validators |
| `recovery/scenario.py` | Builds the ten days, the failure, the restore and the counterfactual |

## Other entry points

- REST: `POST /api/v1/recovery/drill` (no body) returns the report as a `SIMULATED` envelope.
- MCP: `simulate_recovery_drill` on `ffia-local`.
- MCP: `detect_duplicate_records` counts duplicated keys in a catalogued table.
- Offline demo act 8 runs the drill as part of the release gate.

## Tests

`tests/unit/test_recovery.py` covers 20-digit file names, each marker's semantics (including
INSERT without a duplicate check), file-order application, metadata and retention, the content
hash, snapshot integrity, the validators and the full drill.
