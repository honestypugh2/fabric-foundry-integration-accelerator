## Three different boundaries

A domain is a governed business vocabulary and dataset. A tool exposes a bounded capability.
An agent combines a model, context and a managed loop. These boundaries can align, but need
not: one agent can call two permitted tools without creating another agent.

Imagine fictional inventory and sales domains. A stock question routes to inventory; booked
revenue routes to sales. An ambiguous question needs clarification. A sales-only identity must
not gain inventory access merely because a coordinator selected that route.

## When and when not

Use separate agents when domain policy, specialized context or independent ownership requires
it. Do not split solely because two tables or departments exist. Read the P02 and P13 catalogue
entries together: the former describes a preview integration; the latter is a design principle.
