## Design a routing contract

List each fictional domain's vocabulary, allowed facts, tools, owner and denied questions.
Create an independent table of expected routes before asking an assistant to design routing.
Include a single-domain question, an allowed cross-domain question, an ambiguous request and
an unauthorized request. Authorization must be checked for every selected domain.

Compare deterministic rules with a single bounded agent first. Introduce a coordinator only
if these options cannot satisfy the contract. Multi-domain vocabulary does not itself require
multiple reasoning loops.

## Inspect and recover

Record the selected route, returned context and answer separately. If a route is uncertain,
ask for clarification rather than fan out to every domain. If an optional Fabric IQ feature
is unavailable, disclose that status and keep any synthetic routing exercise explicitly LOCAL.
