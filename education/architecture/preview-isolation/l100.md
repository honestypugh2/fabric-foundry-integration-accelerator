## Concepts

- **GA** (generally available) features have a support commitment. **Preview** features do not;
  their behavior, limits and availability can change.
- A **preview feature flag** is a named on/off switch. In this repository the flags live under
  `preview_feature_flags` in `config/customers/example-healthcare.yaml`, and all are `false`.
  For a local demo, `FFIA_PREVIEW_FEATURES=foundry_iq_knowledge` turns one flag on for a single
  process. The committed overlay does not change.
- The **PREVIEW** execution label tells you a result depends on a preview capability. It is
  different from `LIVE` (a real call to a GA service) and `SIMULATED` (no cloud call at all).

## What you will see

Run `ffia demo offline`. Near the end it prints `preview features enabled: none`. That line is
the promise: the default demo never needs a preview feature.

Open the Architecture Studio: preview capabilities such as the Data Warehouse MCP server and
Fabric IQ (ontology) carry a preview state and sit off the main path. Fabric IQ MCP itself is GA
and is shown as documented behavior.
