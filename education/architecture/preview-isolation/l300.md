## Inspect the enforcement

```bash
grep -A6 preview_feature_flags config/customers/example-healthcare.yaml
ffia mcp profiles          # the default profile is LOCAL and read-only
ffia mcp check             # fails if the default profile writes or is not LOCAL
ffia demo offline | grep "preview features"
```

The overlay model exposes `enabled_previews()`. The runtime status endpoint reports the enabled
previews, and the offline demo prints them. A unit test asserts that the example overlay enables
none.

`ffia mcp check` validates every profile. The default profile must be LOCAL and read-only. Write-
capable profiles must be opt-in with per-call approval. Read-only profiles may only contain tools
the pinned catalog marks read-only, minus tools that run arbitrary queries or copy data out.

## Adding a preview capability safely

1. Add a source entry with `status: PREVIEW` and render the registry.
2. Add a flag under `preview_feature_flags`, default `false`.
3. Add an offline simulation that teaches the same idea.
4. Label every result that depends on it `PREVIEW`.
5. If it is an MCP server, add a separate opt-in profile; never touch the default profile.
