## Four isolation mechanisms

| Mechanism | Where | What it blocks |
|---|---|---|
| Overlay flags | `config/customers/<overlay>.yaml` → `preview_feature_flags` | Turning a preview feature on without a reviewed change |
| Execution labels | `ExecutionLabel.PREVIEW` in result envelopes | Presenting preview behavior as a GA or offline result |
| MCP profiles | `config/mcp/profiles.yaml`, `ffia mcp check` | A preview or write-capable server in the default profile |
| Pattern recommendations | pattern catalog (`include_preview`) | Recommending a PREVIEW pattern unless asked |

## A live example

The live Fabric provider lists lakehouse tables through the Lakehouse **List Tables** REST API,
which Microsoft documents as preview. The call is real (`cloud_operation_performed: true`), but
the result is labeled **PREVIEW**, not LIVE. Live access is itself opt-in (`FFIA_FABRIC_LIVE=1`
plus a git-ignored bindings file), so the default experience never reaches it.

## Status vocabulary

Lessons, guides and the source registry use the same words: GA, PREVIEW, DEPRECATED and
UNKNOWN/NEEDS VALIDATION. A status claim cites a source in `docs/research/sources.yaml`.
