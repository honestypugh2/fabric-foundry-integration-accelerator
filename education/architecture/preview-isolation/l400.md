## Design notes

- **Labels are about dependency, not transport.** A live HTTPS call to a preview endpoint returns
  `execution_label: PREVIEW` with `cloud_operation_performed: true`. Evidence consumers can then
  separate "observed in the tenant" from "observed in the tenant through a preview contract".
- **Fail closed at the edges.** The default MCP profile is rendered into the project `.mcp.json`
  and checked in CI, so a preview or write-capable server cannot reach every harness by a quiet
  config edit.
- **Flags are configuration, not code paths.** Flags live in the overlay, so a customer variant
  can enable one preview in its dev environment without forking code.
- **Simulation is a contract.** Each preview topic keeps a LOCAL or SIMULATED equivalent with the
  same teaching objective, so status changes do not break the curriculum.

## Known gaps

- Overlay flags are reported and tested, but not every preview-capable code path reads them yet;
  live, preview-dependent features are additionally gated by explicit opt-in settings.
- Preview status changes upstream; the source registry is re-validated before each release.
- Tenant-specific availability (region, capacity, admin settings) **requires tenant validation**.
