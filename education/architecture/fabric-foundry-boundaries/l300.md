## See each boundary in this repo

Start the control plane with `make run-api` (or `ffia serve api`), then inspect each layer.

```bash
# Context: the medallion catalog served by the Local Fabric Educational Provider (LOCAL)
curl -s localhost:8000/api/v1/runtime/status
curl -s localhost:8000/api/v1/runtime/providers

# Capability access: the local MCP server over stdio (ffia-local, LOCAL)
make run-mcp            # same as: ffia serve mcp

# Authority: list plans; approving your own plan via POST /api/v1/approvals returns 409
curl -s localhost:8000/api/v1/plans
```

| Boundary | Where it is enforced | How to observe it |
|---|---|---|
| Fabric context | `providers/fabric/local.py`, `providers/fabric/port.py` | `POST /api/v1/fabric/read` only accepts allow-listed read operations, never free-form SQL |
| MCP is not authority | `config/policies/tools.yaml`, `mcp/server.py` | No approve, execute, shell or SQL tool exists; `generate_fabric_change_plan` returns a plan and says a human must approve |
| Identity and policy | `policies/engine.py`, `services/changes.py` | Self-approval returns 409; approvals expire and are bound to a destination hash |
| Business-system authority | `services/changes.py` | An approved LIVE change returns `UNAVAILABLE` until an authorized writer exists; it is never redirected to LOCAL |
| Evidence | `audit/store.py`, `GET /api/v1/audit/{correlation_id}` | Every step is recorded under one correlation ID |
| Resilience | `fallback/router.py`, `fallback/circuit_breaker.py` | `FFIA_ENVIRONMENT=hybrid FFIA_SIMULATE_FABRIC_OUTAGE=1 ffia demo offline` |
| Reasoning | `agents/port.py`, `agents/local.py`, `agents/foundry.py`, `agents/routed.py` | `ffia agents ask` shows the label, provider, fallback, grounding and tool calls |

## The release gate tells the truth

`ffia demo offline` runs ten acts. Act 3 makes a real MCP protocol call to `ffia-local` (not a
Fabric MCP server). Act 6 runs the deterministic `LocalSalesAgent` over synthetic sales data and
is labeled `LOCAL`: it answers from governed data through a tool call, never from a model, and it
is a teaching analog - nothing is simulated *as* Foundry. The live `FoundryAgentProvider` is
opt-in (`FFIA_FOUNDRY_LIVE=1` plus a git-ignored `foundry:` binding). Act 7 shows read
fallback (`LOCAL` data in `HYBRID` mode, with a reason) and the circuit breaker opening. Act 8 runs the Open Mirroring
recovery drill, labeled `SIMULATED`.

## Through a coding agent

The root `.mcp.json` registers `ffia-local` (stdio) next to the Microsoft Learn server, so
GitHub Copilot and Claude Code share it. Ask the agent to call `get_runtime_status` and
`get_architecture_pattern` with `P06`: the envelope shows `execution_label`,
`cloud_operation_performed: false` and a `simulation_notice`.

## Tests that prove it

- `tests/unit/test_config_policy_changes.py` - self-approval, expiry, duplicates, LIVE refusal.
- `tests/unit/test_router.py` - fallback labels, breaker states, writes never fall back.
- `make validate` runs lint, strict types, tests with coverage, the privacy scan and the demo.
