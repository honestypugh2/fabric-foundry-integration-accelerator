## Responsibility boundary table

| Concern | Fabric | Foundry / Agent Framework | MCP | Entra identity + policy | Business system |
|---|---|---|---|---|---|
| Data and definitions | **Owns** (OneLake, lakehouse, semantic model, data agent, ontology) | Consumes | Transports calls | Scopes access | Owns its own transactions |
| Row and object security | **Enforces** (workspace roles, item permissions, RLS/OLS) | Must not bypass | Cannot grant | Supplies the identity | — |
| Reasoning, planning, tool choice | — | **Owns** | Describes tools | — | — |
| Evaluation and tracing | Data-quality evidence | **Owns** agent evaluation and traces | Call logs | Sign-in logs | Transaction logs |
| Authorization | Enforces on its resources | Requests approval | **None** | **Owns** | Enforces on its resources |
| Transactional writes | Not the target | Proposes | Carries a request | Approves | **Owns** |

## Identity paths

- **Delegated (user) path.** The person signs in; the agent calls Fabric on their behalf, so
  Fabric applies that person's permissions. Good for exploration and question answering.
- **Agent or service path.** A managed identity or service principal acts for the agent. It
  needs its own least-privilege role assignments and must not inherit an admin's rights.
- **Scoped writer path.** A separate identity performs only approved writes against exact
  targets. The reasoning agent never holds this identity.

## Data flows

1. **Context flow (read):** Foundry agent → MCP or REST tool → Fabric, evaluated under the
   caller's identity.
2. **Reasoning flow:** the agent combines tool results and produces an answer with citations.
3. **Change flow (write):** agent proposes → deterministic validation → human approval →
   scoped writer → business system or Fabric → verify → audit.
4. **Evidence flow:** traces, evaluation results and audit records keyed by correlation ID.

## Trade-offs

- **Data agent vs direct tools.** A Fabric data agent packages context and instructions inside
  Fabric; direct table or DAX tools give the agent more freedom and need more evaluation.
- **GA vs preview.** Preview capabilities (Fabric IQ, ontology, the Foundry Fabric data agent
  tool) stay behind feature flags so the architecture works without them.

## Online vs offline

| Mode | Context | Reasoning | Writes |
|---|---|---|---|
| LIVE | Fabric | Foundry agent (opt-in; no fallback) | Approved writer only |
| HYBRID | Fabric, reads fall back to LOCAL data in `HYBRID` mode, with a reason | Foundry, falling back to the LOCAL agent with a reason | Never fall back |
| OFFLINE | Local Fabric Educational Provider | LOCAL agent over synthetic data (not a model) | LOCAL simulation, labeled `SIMULATED` |
