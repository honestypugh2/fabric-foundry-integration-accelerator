Leveling up Fabric data engineering with GitHub Copilot

What GitHub Copilot actually does for a Fabric data engineer, what Fabric MCP and Fabric Skills are, how Power BI and Foundry fit, and how a team climbs from assisted coding to governed change. Stepped through real architecture diagrams, in the web app, VS Code and the portals.

60 minutes Data engineering and platform leads, architects, analytics engineers Guide hc-01-fabric-mcp-powerbi-medallion-lab Synthetic data only

Overview

Scenario. A healthcare analytics team builds a medallion lakehouse (Bronze, Silver, Gold), a semantic model and a report from seven synthetic CSV sources (guide HC-01). We show how GitHub Copilot changes that work, and how to keep it safe.

Three building blocks, in one sentence each:

  • GitHub Copilot is the agent that plans, writes code, runs commands and calls tools, under your identity and your approvals.
  • Fabric MCP gives the agent hands: tools to read and change Fabric through a standard protocol.
  • Fabric Skills give it know-how: Microsoft-authored procedures for medallion design, Spark, semantic models and reports.

Modes. Offline (the accelerator app and local MCP server, labeled LOCAL), live read-only against the demo tenant (labeled LIVE), and governed change (plans that a person approves).

By the end, the audience can

  • Explain what GitHub Copilot is doing at each step: reading instructions, planning, editing, calling MCP tools and skills, and asking for approval.
  • Explain Fabric MCP (servers, tools, read-only profiles) and Fabric Skills (procedures that call Fabric directly) and why they need different controls.
  • Show how Power BI fits: the semantic model holds business meaning; DAX checks prove the numbers.
  • Climb the L1 → L6 maturity ladder and choose the next level for their team.
  • See Foundry and GitHub Copilot together: GitHub Copilot builds and explains a Foundry agent in code.

Reference architectures

Architecture patterns

P19 · GitHub Copilot CLI + Fabric Skills + MCP MIXED

A terminal agent follows Microsoft-authored Fabric skills and calls Fabric MCP or REST.

Use when: Fast exploration, triage and operator workflows.

Avoid when: Production changes without a reviewed pull request.

Authority: The developer's identity and workspace role.

P09 · Governed MCP GA

Typed MCP tools with owner, version, classification, limits, audit and revocation.

Use when: Sharing capabilities with many agents and developer tools.

Avoid when: Exposing arbitrary shell, SQL, filesystem or URL access.

Authority: Entra identity and the server's own authorization checks.

P20 · Repo-first (Git as source of truth) GA

Agents edit notebooks, TMDL and pipeline definitions in Git; CI validates; deployment applies.

Use when: Anything that must be reviewable, repeatable and auditable.

Avoid when: One-off exploration.

Authority: Pull-request review and branch protection.

P10 · Medallion + AI GA

Bronze preserves, Silver conforms, Gold serves semantic models and agents.

Use when: Every analytical foundation that agents will consume.

Avoid when: Never let agents read Bronze for business answers.

Authority: Layer-level permissions.

P12 · Direct Lake + semantic model + AI GA

Semantic models over OneLake tables give agents governed measures and relationships.

Use when: Governed measures for reports and agents.

Avoid when: When tables are not yet modeled with clear grain and keys.

Authority: Model permissions and RLS/OLS.

P08 · Human-in-the-loop governed action GA

Retrieve, cite, reason, propose, validate, apply policy, approve, scoped write, verify, audit.

Use when: Any write to a business system or Fabric item.

Avoid when: Never skip it for high-impact, destructive, regulated or financially material actions.

Authority: Human approver plus a narrowly scoped writer identity.

P06 · Fabric + Foundry enterprise agent (anchor) MIXED

An application agent combines Foundry knowledge and Fabric context with identity, evaluation, audit and approval.

Use when: Production assistants that read governed data and may propose actions.

Avoid when: Simple Q&A that one data agent or report already answers.

Authority: Entra identity plus policy; humans approve high-impact actions.

Questions and answers

What happens when Fabric MCP isn't available? LIVE

The repository's .mcp.json starts the real Fabric MCP server first and ffia-local as the fallback.

  • The agent says Fabric MCP is unavailable and shows the error. It never switches silently.
  • Reads fall back to the named ffia-local tools (for example list_fabric_workspaces and list_fabric_items), labeled LOCAL. In a hybrid environment those tools read live Fabric metadata through the provider router, which has its own labeled fallback.
  • Writes never fall back to a write. A failed create or upload stops, and the only fallback is a SIMULATED rehearsal (generate_fabric_change_plan).
  • The fallback is never REST or the Azure CLI.

Verified on 2026-10-08 in the demo tenant: Fabric MCP 1.4.0 read-only calls (core_search-catalog, onelake_list-items, onelake_list-tables), and ffia-local returning LOCAL offline and LIVE through the router in hybrid.

Sources: Fabric MCP Server (local) tools reference

What exactly is GitHub Copilot doing in this demo? LOCAL

In VS Code agent mode it:

  • reads the repository instructions (AGENTS.md, .github/copilot-instructions.md);
  • plans;
  • reads and edits files;
  • runs commands;
  • calls MCP tools and skills, asking you to approve tool calls and commands.

In the demo it explains a Spark transform, reads the medallion layers through MCP, plans with a Fabric skill, and proposes a governed change that comes back blocked until a person approves it. It always acts under your identity.

What is Fabric MCP, and can the agent delete things? LIVE

Fabric MCP is a family of MCP servers:

  • Local Fabric MCP server (GA): docs, OneLake, item and Data Factory tools.
  • Fabric IQ MCP (GA): read-only.
  • Data Warehouse MCP (preview).
  • Power BI Modeling MCP.

The local server 1.4.0 has 48 tools: 22 can write and 5 are destructive. So we never expose it whole:

  • Read-only profiles start it with --read-only and an allow-list.
  • Write tools appear only in opt-in profiles with per-call approval.
  • CI checks the rules.

We saw the server refuse a write tool live.

Sources: Fabric MCP Server (local) tools reference, Choose a Microsoft Fabric MCP server

What are Fabric Skills, and how are they different from MCP? LOCAL

Skills are Microsoft-authored procedures (open source, microsoft/skills-for-fabric) for things like medallion design, Spark, semantic models and reports.

Unlike MCP, they tell the agent to call Fabric's REST API directly with az rest, outside MCP allow-lists. So pin and verify them, install only what you need, drop the bundled wildcard MCP configuration, and require approval for every az rest.

Sources: Skills for Fabric overview

How do we level up our team with GitHub Copilot? DOCUMENTED

Climb one level at a time and measure each climb:

  1. L1: GitHub Copilot in the editor, with Fabric items in Git.
  2. L2: repository instructions and documentation MCP.
  3. L3: pinned skills.
  4. L4: read-only Fabric MCP.
  5. L5: governed change through plans, approvals and pull requests.
  6. L6: parallel agents, only for scoped work.

Where does Power BI fit? DOCUMENTED

Business definitions live in the semantic model.

  • GitHub Copilot edits it through Power BI Modeling MCP with the semantic-model-authoring skill, on a local PBIP copy first.
  • Every measure is reconciled with DAX against a governed baseline: 23 of 23 locally; live through the Execute Queries API.

Sources: Power BI Authoring (Modeling) MCP server, Datasets - Execute Queries In Group (Power BI REST API)

How is GitHub Copilot different from Copilot in Fabric? DOCUMENTED

They work in different places and complement each other:

  • Copilot in Fabric works inside the Fabric portal and runs on your Fabric capacity.
  • GitHub Copilot works in developer tools on code and Git-synced Fabric items, with MCP and skills.

Fabric Git integration connects the two.

Can GitHub Copilot write to production? DOCUMENTED

Not in this design:

  • Agents work against a dev workspace.
  • Production changes arrive through pull requests and deployment pipelines.
  • Live writes need a scoped writer, policy approval and a second person.
  • An approved live write is never silently replaced with a simulation.
How does this compare with Claude Code? DOCUMENTED

Both read the same repository files: CLAUDE.md imports AGENTS.md, and the .mcp.json and .claude/skills are shared. They differ in permission modes, hooks and admin controls.

A same-task evaluation is scheduled as a follow-up.
